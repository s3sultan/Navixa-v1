# سياسة تقنية للإلغاء والاسترجاع — حملة مؤسسي NAVIXA

## المبدأ

يجب الفصل دائمًا بين **الحجز** و**الدفع الموثق** و**الاسترجاع**. العداد العام للمقاعد لا يستند إلى الزيارات أو فتح Checkout؛ بل إلى السجل المالي والتشغيلي لكل عرض.

## حالات العرض

| الحالة | وصفها | أثرها على المقعد | أثرها على الوصول |
|---|---|---|---|
| `reserved` | سعر خصص للحساب لمدة 15 دقيقة ولم يتم الدفع | لا يعد مقعدًا مدفوعًا؛ يظهر كحجز مؤقت | لا Plus |
| `expired` | انتهت مهلة الحجز بلا دفع | يحرر الحجز ويعود السعر للمخزون | لا Plus |
| `paid` | وصل Webhook موثق بدفع ناجح | يزيد المقعد المدفوع مرة واحدة | Plus فعّال |
| `refund_pending` | طلب استرجاع قيد المراجعة | لا يتغير العداد حتى قرار الاسترجاع | الوصول وفق السياسة المعتمدة |
| `refunded_pre_use` | استرجاع كامل قبل بدء استفادة Plus وفق السياسة القانونية | يعاد المقعد إلى المخزون إذا كانت هذه القاعدة معتمدة | يُلغى Plus |
| `refunded_after_use` | استرجاع بعد وجود استفادة أو استثناء قانوني/تجاري | لا يعاد المقعد تلقائيًا | يغلق Plus وفق قرار الاسترجاع |
| `chargeback` | نزاع دفع لدى مزود الدفع | يوقف الوصول ويعلم الفريق للمراجعة | معلّق أو مغلق |

## القاعدة المقترحة لإعادة المقعد

يوصى أن يعاد المقعد إلى الحملة فقط عندما تتحقق الشروط التالية مجتمعة:

1. يكون الاسترجاع كاملاً.
2. يثبت عدم بدء الاستفادة من Plus، أو تقرر NAVIXA قانونيًا أن الاسترجاع المبكر يعيد المقعد.
3. تنفذ عملية الاسترجاع بنجاح لدى Moyasar.
4. لم تنته نافذة حملة المؤسسين بعد.
5. لا يكون هذا المقعد هو الأول أو الأخير إلا بمراجعة يدوية، لأنهما يحملان امتيازًا خاصًا.

إذا لم تتحقق الشروط، يبقى المقعد ضمن إجمالي المقاعد المدفوعة تاريخيًا، مع تسجيل الاسترجاع منفصلًا. هذا يمنع تلاعبًا من نوع شراء مقعد رخيص ثم استرجاعه بشكل متكرر لتوليد فرص سعر منخفض.

## تعديلات قاعدة البيانات المقترحة

```sql
CREATE TABLE IF NOT EXISTS navixa_founders_refunds (
  id TEXT PRIMARY KEY,
  award_id TEXT NOT NULL,
  payment_reference TEXT NOT NULL UNIQUE,
  refund_status TEXT NOT NULL,
  refund_amount INTEGER NOT NULL,
  reason_code TEXT NOT NULL,
  requested_at TEXT NOT NULL,
  resolved_at TEXT NOT NULL DEFAULT '',
  inventory_released INTEGER NOT NULL DEFAULT 0,
  admin_note TEXT NOT NULL DEFAULT ''
);

ALTER TABLE navixa_founders_awards
  ADD COLUMN refund_status TEXT NOT NULL DEFAULT '';

ALTER TABLE navixa_founders_awards
  ADD COLUMN access_started_at TEXT NOT NULL DEFAULT '';
```

## API إدارية مقترحة

```http
POST /api/admin/founders/refunds
```

**المدخلات:** `awardId`, `action`, `reasonCode`, `refundAmount`, `releaseInventory`.

ينفذ هذا المسار فقط عبر جلسة مدير موثقة. يجب ألا يعتمد قرار إعادة المقعد على الواجهة؛ بل على معاملة D1 ذرية بعد تحقق رد Moyasar عن الاسترجاع.

## خوارزمية مختصرة

```text
عند طلب الاسترجاع:
  سجل refund_pending
  تحقق من مرجع الدفع وحالة الوصول وتاريخ بدء الاستفادة
  أرسل طلب الاسترجاع لمزود الدفع
  إذا نجح الاسترجاع:
    حدّث award إلى refunded_pre_use أو refunded_after_use
    ألغِ أو علّق Plus بحسب السياسة
    إذا كانت شروط إعادة المخزون متحققة:
      أنقص redeemed_count للفئة السعرية مرة واحدة
      لا تنقصه تحت الصفر
      علّم inventory_released = 1
  إذا فشل الاسترجاع:
    أبقِ الحالة pending أو rejected مع سبب قابل للمراجعة
```

## منع التكرار

- استخدم `payment_reference` فريدًا في جدول الاسترجاعات.
- راجع `inventory_released` قبل أي تعديل للمخزون.
- لا يسمح للحساب نفسه بحجز سعر مؤسس جديد حتى لو أعيد المقعد إلى المخزون.
- لا تعيد السحب أو تغيّر السعر المخصص بسبب فشل الدفع أو الاسترجاع.
- يحدد Webhook موثق فقط حالة الدفع؛ ويحدد رد الاسترجاع الموثق فقط حالة الاسترجاع.

## تجربة العميل

عند الإلغاء، تعرض الواجهة بوضوح: تاريخ انتهاء الوصول، حالة الطلب، وهل طلب الاسترجاع قيد المراجعة. لا تعد الواجهة بالاسترجاع الفوري أو بإعادة السعر قبل أن يصل تأكيد مزود الدفع ويطبق القرار المعتمد.
