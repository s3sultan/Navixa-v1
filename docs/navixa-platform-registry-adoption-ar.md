# ملف إضافة سجل منصات NAVIXA

**الغرض.** يوفّر هذا الملف تعريفًا موحدًا وآمنًا لمنصات NAVIXA الرئيسية وLearning وFitness وKids، حتى تعرف كل منصة عقد الربط والإصدار المتوافق قبل تفعيل التحويل بين المنصات. لا يُعد هذا الملف قناة لمشاركة بيانات المستخدمين أو الأسرار.

> **قاعدة حاسمة:** أضف ملف `navixa-platform-registry.v1.json` كما هو إلى مستودع كل منصة في مسار واضح مثل `docs/`، ولا تضع فيه مفاتيح خاصة أو Cookies أو Grants أو بريد مستخدمين أو أي بيانات دفع.

| المنصة | المجلد المقترح | ما يجب دعمه | نقطة الإتمام |
|---|---|---|---|
| NAVIXA الأساسي | `docs/` | مصدر الهوية والعضوية وJWKS العام | يصدر المنحة فقط للمستخدم المؤهل |
| Learning | `docs/` | `portfolio-sso-es256@1.0.0` | `/api/navixa/complete` |
| Fitness | `docs/` | `portfolio-sso-es256@1.0.0` | `/api/navixa/complete` |
| Kids | `docs/` | `portfolio-sso-es256@1.0.0` | `/api/navixa/complete` |

## طريقة الإضافة المختصرة

ابدأ بنسخ ملف السجل إلى مستودع المنصة من دون تغيير معرّفات المنصات أو روابط HTTPS العامة. بعد ذلك أضف اختبارًا يقرأ `contracts[0].version` ويؤكد أن التطبيق يدعم `portfolio-sso-es256@1.0.0`. يجب أن يعيد مسار الإتمام خطأً محميًا وغير قابل للتخزين عند غياب المنحة، وألا ينشئ جلسة محلية إلا بعد التحقق الكامل من التوقيع والمصدر والجمهور والانتهاء وحالة العضوية.

في كل تغيير لاحق لعقد الدخول الموحد، ارفع رقم الإصدار في السجل أولًا، حدّث اختبارات المصدر والهدف، ثم انشر المنصات المتوافقة قبل إعادة تفعيل التحويل من NAVIXA الأساسي. لا تفعّل رابط منصة لم تصل إلى مسار الإتمام الحي أو لا تستطيع قراءة JWKS العام بطريقة فاشلة الإغلاق.

## قائمة توافق قبل النشر

| الفحص | النتيجة المطلوبة |
|---|---|
| المعرف | يطابق `main` أو `learning` أو `fitness` أو `kids` تمامًا |
| الإصدار | جميع الأطراف تعلن دعم `portfolio-sso-es256@1.0.0` |
| JWKS | طلب HTTPS عام يعيد مفتاح تحقق فقط ولا يحتوي مادة توقيع خاصة |
| غياب المنحة | `400` أو استجابة محمية مكافئة مع `Cache-Control: no-store` |
| منحة صحيحة | إنشاء جلسة قصيرة آمنة ثم تحويل إلى رابط محلي نظيف |
| الخصوصية | لا يظهر Grant في السجل أو التحليلات أو التذاكر أو واجهة المستخدم |
| النطاق | لا يشمل النشر تغييرًا في الدفع أو الأسرار أو محتوى المستخدمين دون اعتماد مستقل |

## إدارة التحديثات بين المنصات

عند بدء أي تعديل يؤثر في الربط، يُحدَّث ملف السجل أولًا ويُضاف بند إلى قائمة عمل المشروع المتأثر. بعد الاختبارات، يُراجع العقد مقابل هذا الملف قبل النشر. وتُسجل في طلب التغيير المنصة، نسخة العقد، نقطة الإتمام، ونتيجة التحقق فقط؛ ولا تُدرج أي بيانات حساب أو محتوى أو أسرار.
