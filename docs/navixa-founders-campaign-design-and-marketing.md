## 3. مخطط قاعدة البيانات المقترح

### جدول الحملة

```sql
CREATE TABLE navixa_founders_campaigns (
  campaign_key TEXT PRIMARY KEY,
  title TEXT NOT NULL,
  start_at TEXT NOT NULL,
  end_at TEXT NOT NULL,
  total_seats INTEGER NOT NULL DEFAULT 100,
  active INTEGER NOT NULL DEFAULT 1,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
```

### جدول مخزون الأسعار

تخزن الأسعار بالهللات لتفادي أخطاء الكسور. مثال: `100` = 1 ر.س و`1200` = 12 ر.س.

```sql
CREATE TABLE navixa_founders_pools (
  campaign_key TEXT NOT NULL,
  award_role TEXT NOT NULL,       -- first | random | last
  price_amount INTEGER NOT NULL,  -- halalas
  seats_total INTEGER NOT NULL,
  reserved_count INTEGER NOT NULL DEFAULT 0,
  redeemed_count INTEGER NOT NULL DEFAULT 0,
  PRIMARY KEY (campaign_key, award_role, price_amount)
);
```

### جدول العرض المخصص للحساب

```sql
CREATE TABLE navixa_founders_awards (
  id TEXT PRIMARY KEY,
  campaign_key TEXT NOT NULL,
  user_id TEXT NOT NULL,
  contact TEXT NOT NULL,
  price_amount INTEGER NOT NULL,
  award_role TEXT NOT NULL,       -- first | random | last
  status TEXT NOT NULL,           -- reserved | paid | expired | cancelled
  intent_id TEXT NOT NULL UNIQUE,
  created_at TEXT NOT NULL,
  reserved_at TEXT NOT NULL,
  expires_at TEXT NOT NULL,
  paid_at TEXT NOT NULL DEFAULT '',
  UNIQUE (campaign_key, contact)
);
```

### سجل الامتيازات الخاصة بالمؤسس الأول

```sql
CREATE TABLE navixa_founder_honors (
  id TEXT PRIMARY KEY,
  user_id TEXT NOT NULL UNIQUE,
  contact TEXT NOT NULL,
  honor_type TEXT NOT NULL,       -- first_gold_founder
  badge_starts_at TEXT NOT NULL,
  badge_ends_at TEXT NOT NULL,    -- سنة من أول دفعة موثقة
  permanent_record INTEGER NOT NULL DEFAULT 1,
  marketing_consent_at TEXT NOT NULL DEFAULT '',
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
```

لا تُستخدم بيانات البريد في التسويق ما لم توجد موافقة مستقلة. يبقى البريد محفوظًا كجزء من الحساب وسجل الامتيازات وإدارة الاشتراك، مع احترام طلبات الحذف والانسحاب من الرسائل التسويقية.

## 4. خوارزمية التخصيص العادل

1. يتحقق النظام من أن الحملة نشطة داخل نافذتها الزمنية.
2. يتحقق من البريد الموثق، حساب NAVIXA، وعدم وجود سجل حملة سابق لهذا البريد أو الحساب.
3. يحذف الحجوزات المنتهية فقط من **المخزون المتاح**، بينما يبقى الحساب الذي انتهى حجزه غير مؤهل لسعر جديد.
4. إذا لم يوجد أي اشتراك مدفوع سابق، يخصص مقعد `first / 1 ر.س`.
5. إذا كان عدد المقاعد المدفوعة 99، يخصص مقعد `last / 1 ر.س`.
6. في بقية الحالات، يختار النظام عشوائيًا من الأسعار المتبقية بوزن يساوي عدد المقاعد غير المدفوعة وغير المحجوزة في كل فئة.
7. ينفذ حجزًا ذريًا: يزيد `reserved_count` فقط عندما يكون `redeemed_count + reserved_count < seats_total`.
8. ينشئ سجل `reserved` مرتبطًا بـ `user_id` و`contact` و`intent_id`، وينتهي بعد 15 دقيقة.
9. عند وصول `payment_paid` من Moyasar أو تحقق الدفع المباشر، تتحول الجائزة إلى `paid`، ويقل `reserved_count` ويزيد `redeemed_count` داخل العملية نفسها.
10. إذا فشل الدفع أو انتهت المهلة، يتحول العرض إلى `expired` ويعود المقعد للمخزون، لكن الحساب لا يسحب سعرًا جديدًا.

### حجز ذري مبسط

```sql
UPDATE navixa_founders_pools
SET reserved_count = reserved_count + 1
WHERE campaign_key = ?
  AND price_amount = ?
  AND redeemed_count + reserved_count < seats_total;
```

يجب التحقق من عدد الصفوف المتأثرة. إذا كان صفرًا، يعاد اختيار فئة متاحة أو يقال إن السعر لم يعد متاحًا. لا يعتمد النظام على قراءة العداد ثم الكتابة لاحقًا؛ لأن ذلك يسبب تجاوز المقاعد مع الدفعات المتزامنة.

## 5. العداد المباشر

### داخل لوحة الإدارة

يعرض المدير كل فئة: إجمالي المقاعد، المحجوز، المدفوع، المتبقي، وآخر وقت تحديث. كما يظهر إجمالي الحملة:

```text
المقاعد المدفوعة: 37 / 100
الحجوزات النشطة: 4
المقاعد المتاحة: 59
```

### داخل صفحة العميل

لا تعرض الصفحة توزيع الأسعار أو هوية أي مشترك. يظهر فقط عداد مختصر مثل:

```text
فرص مؤسسين محدودة متاحة الآن
```

وعند قرب نهاية الحملة يمكن عرض عدد إجمالي تقريبي أو مباشر وفق القرار التسويقي، مثل: `بقي أقل من 20 مقعدًا`. لا تعرض عبارة «المشترك رقم 100» أو السعر النهائي الأخير مسبقًا.
