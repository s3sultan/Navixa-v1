# NAVIXA UI Quality Layer

هذا الملف يحدد طبقة جودة الواجهة الموحدة لمشاريع NAVIXA دون إنشاء نظام تصميم موازٍ أو إضافة اعتماد جديد.

## الهدف

تحسين الواجهة الحالية عبر مراجعة منهجية تلتزم بالنظام الموجود في كل مشروع. القاعدة الأساسية: نطوّر الموجود ولا نضيف مكتبة أو styling system ثانية لمجرد التحسين البصري.

## الأولويات

1. الاتساق مع هوية NAVIXA الحالية.
2. سلامة RTL/LTR بالعربية والإنجليزية.
3. قابلية الاستخدام والوصول.
4. وضوح التسلسل البصري والنصوص.
5. حركة هادئة تخدم الحالة ولا تشتت.
6. أداء جيد دون تضخيم الحزمة.

## قواعد مشتركة

### Typography
- استخدم scale موجودًا بدل أرقام متفرقة.
- العناوين القصيرة يمكن موازنة التفافها، والنصوص الطويلة يجب أن تتجنب السطر اليتيم قدر الإمكان.
- الأرقام المتغيرة ديناميكيًا مثل المؤقتات والعدادات تستخدم tabular numerals لمنع الاهتزاز البصري.
- توازن بصري مستقل للعربية والإنجليزية، ولا يُفترض أن ما يناسب LTR يناسب RTL تلقائيًا.

### Surfaces
- لا تكرر نفس radius بين سطح خارجي وداخلي إذا كان padding يجعل الزوايا تبدو مضغوطة.
- استخدم الحدود للهيكل والحالة، والظلال للعمق عند الحاجة فقط.
- المحاذاة البصرية مقدمة على المحاذاة الحسابية حين تبدو الأيقونة أو النص غير متوازن.

### Interaction
- الحد الأدنى المستهدف للمس على الجوال 44×44px، مع عدم تداخل مناطق اللمس.
- حالات العناصر التفاعلية: default, hover, focus, active, disabled, loading, success, error, empty حسب الحاجة.
- حالة focus مرئية دائمًا ولا تعتمد على اللون فقط.

### Motion
- لا تستخدم animation متكرر على التفاعلات عالية التكرار.
- الانتقالات التفاعلية يجب أن تكون قابلة للمقاطعة قدر الإمكان.
- الخروج أكثر هدوءًا من الدخول.
- احترم prefers-reduced-motion.
- لا تستخدم transition: all.
- لا تستخدم will-change إلا عند وجود مشكلة فعلية ومع خصائص قابلة للتركيب مثل transform أو opacity أو filter.

### Icons
- استخدم نظام الأيقونات الموجود أصلًا في المشروع.
- لا تخلط مجموعات أيقونات متعددة في نفس السطح.
- استخدم currentColor للحالات بدل أصول منفصلة عندما يكون ذلك مناسبًا.
- الأيقونات الاتجاهية فقط هي التي تنعكس مع RTL، لا تعكس الأيقونات غير الاتجاهية.

### Performance
- ممنوع إضافة dependency لتحسين بصري يمكن تنفيذه بالنظام الحالي.
- قيّم وزن العميل وإعادة التصيير قبل إدخال animation library جديدة.
- في NAVIXA الأساسي تحديدًا، استخدم CSS/React الموجود ما لم توجد حاجة مثبتة لمكتبة إضافية.

## أسلوب المراجعة

### Quick
للمسار الرئيسي وأعلى الحالات استخدامًا. حد أقصى 5 ملاحظات HIGH/MEDIUM.

### Full
يشمل typography, surfaces, interactions/motion, icons, accessibility/performance. حد أقصى 15 ملاحظة فعلية دون حشو.

لكل ملاحظة:
- Severity: HIGH / MEDIUM / LOW
- Location
- Current behavior
- Proposed change
- User impact

## Stress Test للمكونات

قبل اعتماد مكون مهم، اختبر عند الإمكان:
- نص قصير وطويل جدًا
- عربي RTL وإنجليزي LTR
- loading
- empty
- error
- disabled
- narrow mobile
- medium tablet
- wide desktop
- keyboard focus
- reduced motion

## قواعد خاصة بالمشاريع

### NAVIXA الأساسي
- لا تُضاف مكتبة motion أو icon جديدة حاليًا.
- الأولوية لخفة العميل، RTL، التنقل، الحالات، المؤقتات والعدادات، ووضوح لوحة الإدارة.

### NAVIXA Kids
- استخدم Radix وFramer Motion وLucide الموجودة بالفعل بدل أي بديل موازٍ.
- زد التشدد في touch targets والوصول والحالات الواضحة للأطفال.

### English Learning
- استخدم الأدوات الموجودة أصلًا.
- الأولوية للقراءة، line length، hierarchy، direction، وحالات التدريبات.

### NAVIXA Fitness
- استخدم الأدوات الموجودة أصلًا.
- طبّق tabular numerals على المؤقتات والعدادات والقيم المتغيرة.
- الحركة تعطي feedback فقط ولا تعيق بدء التمرين أو الانتقال.

## شرط الدمج

لا يُعتمد تغيير واجهة إذا:
- أدخل نظام styling ثانٍ دون حاجة.
- أضاف dependency بلا مبرر تقني.
- كسر RTL/LTR أو keyboard/focus.
- ترك overflow أو tap targets غير قابلة للاستخدام.
- زاد الحركة بطريقة مشتتة أو غير قابلة للتقليل.
- فشل الاختبار أو البناء ذي الصلة.

## حقوق الطرف الثالث

هذه الوثيقة صياغة داخلية خاصة بـ NAVIXA ولا تنسخ ملفات أو نصوص مستودعات خارجية. إذا استُخدم كود طرف ثالث لاحقًا، يجب فحص الرخصة والالتزام بها داخل المستودع دون إظهار نسب غير مطلوبة في واجهة المنتج.
