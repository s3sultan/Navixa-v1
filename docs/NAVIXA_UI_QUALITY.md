# NAVIXA UI Quality Layer

هذه الوثيقة تضبط جودة الواجهة داخل النظام الحالي دون إنشاء نظام تصميم موازٍ أو إضافة اعتماد غير ضروري.

## الأولويات
1. وضوح الاستخدام قبل الزينة.
2. الالتزام بهوية NAVIXA الحالية.
3. سلامة RTL/LTR.
4. تجربة متماسكة على الجوال والتابلت وسطح المكتب حسب نطاق المهمة.
5. وصول جيد وحالات تفاعل واضحة.
6. حركة هادئة وأداء خفيف.

## قواعد عامة

### النصوص والتسلسل البصري
- استخدم المقاسات والمسافات الموجودة بدل أرقام عشوائية متفرقة.
- اختبر النص القصير والطويل بالعربية والإنجليزية.
- المؤقتات والعدادات يجب ألا تسبب قفزًا أو اهتزازًا بصريًا غير ضروري.

### الأسطح والمحاذاة
- الحدود للهيكل والحالة، والظلال للعمق عند الحاجة فقط.
- المحاذاة البصرية مقدمة على المحاذاة الحسابية إذا بدت الأيقونة أو العبارة غير متوازنة.
- لا تضف طبقات زخرفية تقلل الوضوح أو تزيد ثقل الصفحة.

### التفاعل
- مناطق اللمس على الجوال يجب أن تكون واضحة وغير متداخلة.
- وفّر حالات default وfocus وactive وdisabled وloading وempty وerror وsuccess حسب حاجة المكوّن.
- لا تعتمد الحالة المهمة على اللون وحده.

### الحركة
- الحركة للـfeedback أو توضيح الانتقال، وليست هدفًا بذاتها.
- احترم prefers-reduced-motion.
- تجنب transition: all وwill-change غير المبرر.
- لا تستخدم حركة متكررة في عناصر كثيرة الاستخدام إذا كانت ستشتت أو تستهلك الأداء.

### الاستجابة
- أي تغيير على الجوال يراجع على عرض ضيق ومتوسط.
- أي تغيير على التابلت يراجع بالوضعين الرأسي والأفقي عند الحاجة.
- إذا كانت المهمة مخصصة للجوال/التابلت فقط، يظل سطح المكتب دون تغيير بصري.
- يمنع horizontal overflow غير المقصود.
- راعِ safe-area وارتفاعات الشاشة الديناميكية عند الواجهات القريبة من حواف الجوال.

### الأداء
- لا تضف dependency لتحسين بصري يمكن تنفيذه بالنظام الحالي.
- لا تضف أصولًا أو مكتبات أو ملفات خارجية لمجرد تحسين الشكل.
- راجع أثر المكوّن على العميل وإعادة التصيير قبل إضافة سلوك بصري مكلف.

## Stress Test للمكونات
عند مراجعة مكوّن مهم، اختبر ما ينطبق من التالي:
- نص قصير وطويل جدًا
- عربي RTL وإنجليزي LTR
- loading وempty وerror وsuccess
- disabled
- narrow mobile
- medium tablet
- wide desktop
- keyboard focus
- reduced motion

## أسلوب المراجعة
لكل ملاحظة واجهة مهمة سجل:
- Severity: HIGH / MEDIUM / LOW
- Location
- Current behavior
- Proposed change
- User impact

## شرط الدمج
لا يعتمد تغيير واجهة إذا كان:
- ينشئ نظام styling موازٍ دون حاجة.
- يضيف dependency بلا مبرر تقني.
- يكسر RTL/LTR أو keyboard/focus.
- يسبب overflow أو مناطق لمس سيئة.
- يغير سطح المكتب خارج نطاق مهمة الجوال/التابلت.
- يزيد الحركة بصورة مشتتة أو غير قابلة للتقليل.
- يفشل اختبارًا أو بناءً ذا صلة.
- يدخل مواد أو أصولًا أو نصوصًا أو أكوادًا خارجية مخالفة لسياسة NAVIXA.

## قاعدة الحقوق والمصادر
هذه الوثيقة داخلية ومكتوبة لـ NAVIXA. الاستفادة من المصادر الخارجية تقتصر على الأفكار العامة، ثم يبنى التنفيذ بصورة مستقلة داخل المشروع. لا تُدخل أكواد أو ملفات أو أصول أو نصوص أو شعارات أو قوالب أو إشعارات حقوق خارجية دون مراجعة قانونية وتقنية صريحة للاستخدام المحدد.
