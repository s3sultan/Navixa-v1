# NAVIXA Micro Interactions

الحالة: معتمد كمسار تصميم داخلي، والتنفيذ يبدأ تدريجيًا بعد استقرار ربط Voice Engine.

## الهدف

إضافة استجابات وحركات صغيرة تجعل NAVIXA أوضح وأسرع إحساسًا دون تغيير الهوية أو إزعاج المستخدم أو زيادة الاعتماديات بلا حاجة.

## قواعد NAVIXA الملزمة

1. التنفيذ باسم وهوية NAVIXA فقط.
2. لا يُنسخ كود أو مكوّن أو ملف أو أصل بصري من مكتبات خارجية إلى المنتج.
3. لا CLI خارجي ولا Registry خارجي داخل المشروع لهذا المسار.
4. لا شعارات أو أسماء أو Credits خارجية في واجهة NAVIXA.
5. لا dependency جديدة للحركة ما دام CSS وواجهات المتصفح الحالية تكفي.
6. أي فكرة خارجية تعامل كمرجع سلوكي فقط، ثم تُبنى من الصفر داخل NAVIXA.
7. احترام `prefers-reduced-motion` إلزامي.
8. الحركة لا تؤخر الإجراء ولا تخفي حالة مهمة ولا تمنع الوصول بلوحة المفاتيح.
9. تجنب الحركة المستمرة غير الضرورية، والوميض، والقفزات الكبيرة، والمؤثرات المرهقة.
10. الأداء أولًا: استخدم `transform` و`opacity` قدر الإمكان، وتجنب تحريك خصائص تسبب layout متكررًا.
11. لا تغييرات واسعة على التصميم الحالي. كل حركة تُضاف كتطوير صغير قابل للرجوع.
12. قبل الدمج: lint + tests + UI smoke + build + مراجعة بصرية على الجوال وسطح المكتب.

## المرحلة الأولى

### الاستماع الصوتي
- زر التشغيل: استجابة ضغط خفيفة وواضحة.
- حالة الاستماع: انتقال هادئ بين جاهز / يستمع / توقف / خطأ.
- مؤشر الميكروفون: نبضة محدودة أثناء الاستماع فقط، وتتوقف مع `prefers-reduced-motion`.
- اكتشاف الاسم: إبراز قصير للحالة دون وميض أو اهتزاز مزعج.
- الأخطاء والصلاحيات: ظهور رسالة الحالة بسلاسة مع بقاء النص مقروءًا فورًا.

### مراقبة الشاشة
- انتقال حالة التفعيل والإيقاف دون تغيير تخطيط البطاقة.
- إبراز قصير عند اكتشاف تغيير مهم فقط.

### المهام والمواعيد
- تأكيد حفظ قصير وغير معيق.
- فتح وإغلاق البطاقات بدون قفزات مفاجئة.

### التلخيص والذكاء
- Loader داخلي بسيط وخفيف، بلا رسوم مشتتة أو dependency إضافية.
- انتقال واضح من المعالجة إلى النتيجة.

## حدود الحركة الافتراضية

- الضغط: 80–140ms.
- تغيير الحالة: 160–240ms.
- ظهور بطاقة/رسالة: 180–280ms.
- لا حركة زخرفية طويلة تتجاوز 500ms في الاستخدام اليومي إلا لسبب واضح.

## بوابة الاعتماد

أي Micro Interaction جديدة يجب أن تحقق:
- الغرض واضح.
- لا dependency جديدة بلا ضرورة.
- لا كود أو حقوق خارجية منسوخة.
- تعمل مع لوحة المفاتيح واللمس.
- تحترم reduced motion.
- لا تسبب layout shift ملحوظًا.
- لا تغيّر وظيفة NAVIXA الأساسية.
- اجتازت الاختبارات والمراجعة البصرية قبل الدمج والنشر.

## المرجع الخارجي الذي ألهم الدراسة

تمت دراسة مكتبة خارجية للحركات الصغيرة كمصدر أفكار فقط. ترخيصها MIT يسمح بالاستخدام بشروطه، لكن سياسة NAVIXA في هذا المسار أكثر تحفظًا: لن ننسخ مكوناتها أو نشغل CLI/Registry الخاص بها، وبالتالي لا ندخل كودها أو أصولها إلى NAVIXA. نبني التنفيذ داخليًا من الصفر وفق القواعد أعلاه.
