# NAVIXA Development Protocol

هذا المستند يحدد بوابة التطوير الداخلية في NAVIXA لتقليل الأعطال والتغييرات غير المقصودة.

## مسار العمل

1. **تحديد المطلوب**
   - وصف السلوك المطلوب بلغة NAVIXA.
   - تحديد الملفات والنطاق وما لا يجب تغييره.
   - تسجيل أثر الأمان والخصوصية والحسابات والاشتراكات والترجمة والنشر عند الحاجة.

2. **تنفيذ معزول**
   - العمل على فرع مستقل.
   - حصر التغيير في النطاق المعتمد.
   - عدم إعادة تصميم أجزاء أخرى أثناء تنفيذ المهمة.

3. **تحقق أولي**
   - تشغيل أصغر اختبارات مرتبطة بالتغيير أولًا.
   - تشغيل lint والاختبارات والبناء عند لمس كود مشترك.
   - عدم الدمج مع فشل أي فحص مانع.

4. **مراجعة مستقلة**
   - مراجعة الـdiff من سياق مختلف عن المنفذ متى كان ذلك ممكنًا.
   - فحص الصحة الوظيفية، الانحدارات، الأمان، الخصوصية، المصادقة، الاستحقاقات، الدفع، الترجمة، الأداء والنشر حسب نطاق المهمة.
   - تصنيف النتيجة: `CLEAR` أو `MINOR` أو `MAJOR` أو `BLOCKER`.

5. **إصلاح وإعادة مراجعة**
   - لا يدمج أي تغيير يحتوي `MAJOR` أو `BLOCKER`.
   - بعد الإصلاح يعاد فحص الجزء المتغير وما يتأثر به مباشرة.

6. **البوابة النهائية**
   - نجاح الاختبارات المناسبة.
   - عدم وجود ملفات أو تغييرات غير مرتبطة.
   - عدم وجود أسرار أو بيانات حساسة أو سجلات تصحيح مؤقتة.
   - الحفاظ على هوية NAVIXA وحدود المشاريع.

## حدود المشاريع

NAVIXA وNAVIXA Kids وNAVIXA English Learning وNAVIXA Fitness وغيرها من المشاريع التابعة كيانات منفصلة في الواجهة والمنطق الخاص بكل مشروع. أي منطق مشترك للحساب أو الاستحقاق يجب مراجعته على جميع المشاريع التي يتأثر وصولها به قبل الدمج.

## قاعدة المصادر الخارجية

- لا يُنسخ كود أو ملفات أو أصول أو نصوص أو Prompts أو قوالب أو تعليقات أو شعارات أو إشعارات حقوق من مستودع أو خدمة خارجية إلى NAVIXA دون مراجعة قانونية وتقنية صريحة لذلك الاستخدام المحدد.
- عند الاستفادة من مصدر خارجي، الأصل هو أخذ الفكرة العامة فقط ثم بناؤها بصورة مستقلة داخل NAVIXA.
- قبل إدخال أي اعتماد خارجي جديد يجب مراجعة الترخيص وحقوق إعادة التوزيع ومتطلبات الإسناد والإشعارات والعلامات التجارية والإفصاح عن المصدر.
- إذا تعارضت الالتزامات مع متطلبات NAVIXA فلا تُدخل المادة أصلًا، ولا تُحذف حقوق واجبة لإخفاء أصلها.

## قائمة المراجع

- النطاق مطابق للمطلوب.
- لا تغييرات جانبية.
- الفحوص ذات الصلة ناجحة.
- المصادقة والجلسات لم تتضرر.
- حدود الاشتراك والاستحقاق محفوظة.
- لا أسرار أو بيانات حساسة.
- لا جمع أو تسجيل غير آمن للبيانات.
- لا حقوق أو أسماء أو أصول خارجية دخلت بالخطأ.
- اتجاه العربية والإنجليزية سليم عند تأثر الواجهة.
- أثر النشر والتراجع مفهوم.

## حكم الدمج

- `CLEAR`: صالح للدمج ضمن النطاق الذي تمت مراجعته.
- `MINOR`: يحتاج قبولًا صريحًا للملاحظات الصغيرة قبل الدمج.
- `MAJOR`: لا يدمج حتى الإصلاح.
- `BLOCKER`: يتوقف مسار الإصدار حتى المعالجة.
