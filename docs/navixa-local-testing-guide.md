# دليل اختبار NAVIXA المحلي

## المبدأ

يعتمد NAVIXA على **npm** وملف `package-lock.json` نفسه المستخدم في سير النشر الإنتاجي. لا تستخدم `pnpm` في هذا المستودع؛ إذ إن إعداد pnpm المحلي غير معتمد في سير النشر وكان سببًا في تعطيل بناء الحزم الاختيارية محليًا.

## الأوامر المعتمدة

| الغرض | الأمر | ما يتحقق منه |
|---|---|---|
| تثبيت نظيف مطابق للنشر | `npm ci` | قراءة القفل نفسه وتثبيت تبعيات Node 22 |
| تحقق يومي قبل التعديل | `npm run test:local` | ESLint، اختبارات الأمان، واختبار واجهة الجوال |
| تحقق كامل قبل نشر حساس | `npm run test:verify` | التحقق اليومي ثم بناء Vinext/Worker |
| تحقق نظيف كامل | `npm run test:clean` | يعيد تثبيت الحزم ثم ينفذ التحقق الكامل |
| اختبار الأمان فقط | `npm test` | المصادقة، حماية API، الحسابات، Telegram، والتزامن |
| اختبار الواجهة فقط | `npm run test:ui` | خادم NAVIXA محليًا وChromium بنمط الجوال |
| البناء فقط | `npm run build` | بناء Vinext/Worker قبل النشر |

## التسلسل الموصى به

قبل أي نشر ذي أثر على الحسابات أو الدفع أو البريد أو Telegram، نفذ `npm run test:verify`. إذا تغيّر القفل أو تبعيات المشروع، نفذ `npm run test:clean` بدلًا منه. أما `npm run test:local` فهو الفحص السريع الذي يطابق مرحلة الاختبارات في سير النشر. لا تفتح التحصيل الحي أو تغيّر أسرار Cloudflare اعتمادًا على نجاح البناء وحده؛ يلزم اختبار المسار الإداري والـWebhook المنفصلين.

## معالجة الأعطال

إذا فشل `npm run test:ui` لأن الخادم لم يبدأ، اقرأ ناتج Vite/Wrangler أولًا ولا تعدّل المهلات عشوائيًا. إذا فشل `npm ci`، قارنه مع `package-lock.json` ولا تستخدم `npm install` لتجاوز القفل. أما تنبيهات `npm audit` فهي مراجعة أمنية منفصلة؛ لا تستخدم `npm audit fix --force` تلقائيًا لأنه قد يغيّر نسخًا رئيسية ويؤثر على الدفع أو المصادقة.
